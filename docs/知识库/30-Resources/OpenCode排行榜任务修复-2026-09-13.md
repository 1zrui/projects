# OpenCode Go 排行榜任务：源站改版导致"静默推旧缓存"（2026-09-13）

## 现象
手动执行 cron 任务 `4e5bb47697f0` 时发现：任务天天报 ok，但推的内容是**旧的**（9 条、还把 MiMo 的 30,100 错挂到 DeepSeek V4.1 Flash 上）。

## 根因（两层）
1. **源站改版**：opencode.ai/zh/go 的 DOM 从 `data-item / data-kind="go" / data-value / data-name` 改成
   `data-slot="model-row" data-model="id"` + `<bdi>Name</bdi>` + `data-slot="usage-value"`。
   中间那版脚本按 `data-slot="requests"` 写，也已经对不上。
2. **脚本"抓取失败不抛异常"** → 直接把上次的 `latest.txt` 当本次结果打印 → cron 记 ok、推旧数据。
   这类"静默陈旧"比直接报错更坑（跟 BlockBeats 那个 README 里写的历史教训同类）。

## 两份脚本（⚠️ cron 用的是前者）
- **`/home/ubuntu/.hermes/scripts/fetch_ranking.py`** ← cron `script: fetch_ranking.py` 解析到这里，**必须改这份**
- `/home/ubuntu/workspace/opencode-ranking/fetch_ranking.py` ← 工作区副本（写 latest.json/latest.txt/history.jsonl 到 workspace 目录）

两份都按新 DOM 重写了：
```python
for chunk in html.split('data-slot="model-row"')[1:]:
    mid  = re.search(r'data-model="([^"]+)"', chunk)
    name = re.search(r'<bdi>([^<]+)</bdi>', chunk)
    val  = re.search(r'>([\d][\d,]*)\s*<', chunk)   # 名字后的第一个数字 = 每5小时请求数
```
