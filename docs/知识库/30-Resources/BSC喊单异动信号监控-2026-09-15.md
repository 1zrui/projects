# BSC 喊单/异动信号监控（2026-09-15 上线）

## 需求（大哥原话）
> "不是让你买，你第一时间给我信号，我决定买不买入。不是出新币就给我信号，要有利好信息有人喊单，就比如今天 CZ 喊永生果蝇一样。"
> "盯谁没有固定目标，（能不能）换成任何人"

**结论：盯人不现实（全网推文 = X 付费 firehose），改盯钱 —— 谁喊单都会先有钱进来，链上藏不住。**

## 交付物
- 脚本：`~/meme-monitor/bsc_signal.py`
- 服务：`systemd bsc-signal.service`（**enabled + active**，开机自启，Restart=always，~13MB 内存）
- 状态/日志：`signal_state.json`、`signal_events.jsonl`、`signal.log`
- 推送目标：QQ 群 **624127517（消息推送）**
- 看日志：`journalctl -u bsc-signal -f`

## 工作流
```
① 链上扫描（每轮 ~50-100s）
   量榜滚动 1~10 页 + 新池 2 页 + 热词搜索 3 个 + DexScreener 推广位
        ↓ 命中阈值
② 分级
   🔴 A 级（立刻推）：5min ≥ +150% 且成交 ≥ $50K 且买笔 ≥ 150 且流动性 ≥ $30K
   🟡 B 级（30 分钟汇总一条）：5min ≥ +40% 且成交 ≥ $15K，或"5min 量占过去 1 小时 70%+"
        ↓
③ GoPlus 风控快检（免费，直连）
   蜜罐 / 买卖税 / 可增发 / owner 权限 / LP 锁定 / top10 持仓 / 持有人数
        ↓
④ 推 QQ 群（人类决定买不买，脚本不下单）
```

## 关键实测坑（都是这次踩的）
1. **网络拓扑必须写死，不能靠环境变量**：
   - GeckoTerminal / DexScreener **必须走代理**（直连 HTTP 000）
   - GoPlus / api.sgroup.qq.com **直连**（走代理反而慢/失败）
   - 所以脚本里用两个 opener（`_proxy_opener` / `_direct_opener`），systemd 不给任何代理环境变量
2. **GeckoTerminal 免费版只能翻到第 10 页**（`/pools?page=11` 起 401 Unauthorized）→ 滚动扫描上限 10 页 ≈ 200 池
3. **Gecko 限流是出口 IP 维度**，代理出口是共享的 → 每轮之间 sleep 3s，429 时退避 6s×n 重试
4. **DexScreener 按关键词搜能命中币名**（CZ 喊什么梗，币名里就有："果蝇"搜出来确实有币叫「果蝇」），但结果按相关性排、**不含"正在冲"的信息**，只能用来"反查名字"，不能当发现主力
5. **量榜前列全是主流老池**，真正在冲的币不在里面 → 必须靠"滚动覆盖 + 自己算突变"，不能指望榜单

**两种推送**：
1. 📢 **利好快讯**：币安官方公告 + 命中利好词 → 直推原文（例：实测推到 "Binance Alpha Trading Competition: PIEVERSE"）

**踩坑**：
- 利好词必须**用 `\b` 词边界**：`"list"` 会被 `"delist"`（下架）命中，把利空当利好推 → 还加了负向词表（delist/removal/suspend/下架/移除/暂停）直接跳过
- `t.me/s/` 只给最近 20 条消息，靠 `data-post` 里的消息 ID 去重 → 记 `tg_seen[channel]`
- 社媒轮询间隔 120s 单独控制（TG 页面每条 130KB，别每轮都拉）

## 真正的技术结论：发现层要从"API 轮询"换成"链上事件直读"

现在的瓶颈是**延迟**：轮询 GeckoTerminal / DexScreener API，新池要 15~60 秒才知道。实测结果：

- **BSC 公共节点直连就能用**（不用代理、不用自建、不要 API key）：`https://bsc-rpc.publicnode.com` ✅
  （`bsc-dataseed.binance.org` 要代理；`binance.llamarpc.com` 不通）
- **直接读链上事件极快**：`eth_getLogs` 拉 PancakeSwap Factory 的 `PairCreated`，**200 个区块（≈2.5 分钟链上时间）只用 0.89 秒**，实测抓到 3 个新建池
- 结论：**新池 3 秒内就能知道**，比现在快 20 倍以上，而且免费

## 链上直读层（2026-09-16 01:15 上线）—— 把"发现"从 API 轮询换成直读链上

**为什么**：API 层（GeckoTerminal/DexScreener）新池要 15~60 秒才知道。链上直读 **3 秒内**。

**部署**：
- 脚本 `~/meme-monitor/bsc_chain.py`，服务 `systemd bsc-chain`（enabled+active，~14MB）
- 和 API 层**共用冷却**（写进 `signal_state.json` 的 pushed 表），同一个币不会被两层各推一遍
- 依赖 `bsc_signal.py` 的推送/风控/格式化函数，**启动必须调 `bsig.load_qq_env()`**，否则 `push_qq` 拿不到 QQ_APP_ID 会静默失败

**实测性能**：
- 新池发现延迟 **~3 秒**（原来 15~60 秒）
- 2 分钟抓到 **27 个新建池**（含「果蝇」「永生苍蝇」「币安时间」「Time Flies」这些 CZ 梗币）
- `eth_getLogs` 拉 200 区块只要 **0.89 秒**

**BSC 公共节点限制（血泪实测，换节点必看）**：
| 节点 | 地址数上限 | 区块范围上限 | 备注 |
|---|---|---|---|
| `https://bsc-rpc.publicnode.com` | 6 | 100+ | ⚠️ **不给 python-urllib 默认 UA，会 403**，必须带 `User-Agent: Mozilla/5.0` |
| `https://1rpc.io/bnb` | 11+（实测 11 个 OK） | ≤50 | 扫 Swap 用这个 |
| `https://bsc.blockrazor.xyz` | 6 | 25 | 备用 |
| `https://bsc-dataseed.binance.org` | - | - | 要走代理才通 |

所以分工：**publicnode 扫新池（单地址），1rpc.io/bnb 扫 Swap（多地址）**，地址 8 个一组、区块 20 块一组分块查。

**合约常量**：
- PancakeSwap V2 Factory：`0xca143ce32fe78f1f7019d7d551a6402fc5350c73`
- `PairCreated` topic：`0x0d3648bd0f6ba80134a33ba9275ac585d9d315f0ad8355cddefde31afa28d0e9`
- `Swap` topic：`0xd78ad95fa46c994b6551d0da85fc275fe613ce37657fb8d5e3d130840159d822`
- WBNB：`0xbb4cdb9cbd36b01bd1cbaebf2de08d9173bc095c`
- ⚠️ PancakeSwap **V3** Factory（`0x0BFbCF9fa4f9C56B0F40a671Ad40E0805A091865`）实测 300 区块 0 条日志 → **meme 主战场在 V2，V3 不用管**

**Swap 解析要点**：V2 `Swap` 的 data = amount0In/amount1In/amount0Out/amount1Out（各 32 字节）。判断买卖：**代币从池子里流出（token out > 0）= 有人买**；代币流进池子 = 卖。要先调 `token0()`（选择器 `0x0dfe1681`）确认代币在 reserve 的哪一侧。用 `(txHash, logIndex)` 去重。

**链上阈值（按凌晨实测校准）**：

- 🚨 爆发 A：池龄 ≤6 小时 且 1 分钟买笔 ≥18 且 净买入 ≥$2500 且 流动性 ≥$8K
- 同池 40 分钟冷却；每轮最多推 3 条

### 核心教训：判断"会不会被抽跑"只看一件事 —— LP 在谁手里

- LP 在普通钱包里 → 部署者随时能抽 ❌
- 链上直读法：`pair.totalSupply()` + `pair.balanceOf(0x0)` + `pair.balanceOf(0xdead)`

### 但**不能**做成硬门槛（重要）

- LP 已锁 → 正常门槛，且标注 ✅

## 新增字段：持币人数 + 前十地址占比（2026-09-16 09:05，大哥要求）

2. **`find_shill(名字)`**：在最近 3 小时的「喊单频道 + 快讯」里搜这个币的名字/梗 → 返回来源、几分钟前、原文片段
3. **每个信号都带**：
   - `📣 喊单加持：BWE快讯 3 分钟前提过「永生果蝇」` + 原文
   - 或 `📣 喊单加持：无（纯链上资金，公开渠道没看到有人喊）`
4. **信号强度评级**（三项计分）：
   - 链上钱在进（1 分钟 ≥4 买单且净买入为正）
   - 有人喊（find_shill 命中）
   - LP 已锁（≥50%）
   - → 🟢 三项齐 / 🟡 两项 / 🟠 单项

### 诚实的边界

## 前十占比的口径对齐（2026-09-16 10:00，大哥拿币安钱包 Meme 的数字来对账）

**问题**：我显示 25.83%，大哥在**币安钱包 → Meme 板块**看到 17.5%。

**逐个地址链上查证**（这个币 0xf545…7777）：

| 地址 | 占比 | 实际身份（eth_getCode 验证） |
|---|---|---|
| 0x587b83d6…877c | 5.77% | **合约**（23906 字节）← 币安钱包/工具会隐藏 |
| 0x51b124d3…11ab | 4.16% | 合约 = PancakeV2 池子 |
| 0xd8ff4025…4357 | 1.54% | 合约（7951 字节） |
| 0x0000000000ef40…e850 | 1.48% | 合约（17755 字节，发射台 Flap 的） |
| 其余 6 个 | 1.3~3.8% | EOA 散户 |

**口径对照**：
- 全部前十（含合约）= 25.83%（我原来的显示，错）
- 剔合约 + 留池子 = **17.04%** ← **币安钱包 Meme 的口径**（大哥的 17.5%，差 0.5% 是快照时间差）
- 剔合约 + 剔池子 = 12.89%

**已固定为**：剔合约地址、池子仍计入前十、另外单独报"池子占 X%"。

**教训**：**GoPlus 的 `is_contract` 字段不可信** —— 它把一堆 EOA 标成合约（也把真合约标错过）。判断是不是合约必须自己 `eth_getCode` 看代码长度（>100 字节才算真合约）。

## 已知限制（诚实清单）
- 覆盖：量榜前 200 池 + 新池 + 热词 + 推广位，**不是全链全池**；纯新盘（池龄<2min）暂不推（噪音太大）
- 延迟：链上数据是 Gecko 索引的，**大约 15~60 秒**；A 级从"钱开始冲"到你手机上约 1~2 分钟
- **社媒层（"谁在喊"）还没做**（phase 2）：需要 X 登录态轮询（桌面 Chrome 里 x.com 已登录，实测 200）或复用 BlockBeats 快讯关键词
- 仿盘：热点一出会冒出几十个同名币，信号里的 CA 要自己核对

### 这一轮踩的坑（真实教训）
1. **`any()` 忘了写生成器** —— `any(w in name for w in words)` 写成 `any(w in name)` → `TypeError: 'bool' object is not iterable` → 叙事层每轮崩，功能从上线起**一次都没跑过**。教训：**新功能上线后必须看日志确认它真的执行了**，不能只看代码"应该没错"。
2. **关键词子串匹配**——`ai` 命中 `p-a-i-d`、`MARA`（"矿企买比特币"的新闻配了个叫 paid 的垃圾币）→ 英文关键词改用**词边界**（`(?<![a-z0-9])kw(?![a-z0-9])`），中文仍用子串。
3. **泛词不能做叙事触发**——`ai`/`cat`/`dog`/`meme` 这类词只会撞垃圾币。叙事触发词收窄到 23 个"名人/大所/具体梗"。
4. **重启翻旧账**——`news_seen` 因崩溃没落盘 → 重启后把老快讯重推一遍。加了 45 分钟时效。
5. **只用接口数据算不出币安钱包的数字**——币安钱包 Meme 的"前十占比"＝**剔除合约地址、但池子算在内**；GoPlus 的 `is_contract` 还会把 EOA 标成合约，必须用 `eth_getCode` 逐个验证代码长度。
