# 网关"自己挂了"排查：其实是被人手动 kill（2026-09-12 00:31）

## 结论
网关没崩，是**有人在 root 控制台里手动 kill 了两次**，然后又手动重启。

## 时间线（全部来自 journal + auth.log + /root/.bash_history）
```
00:30        腾讯云控制台 OrcaTerm 开了 3 个 root 会话（pts/1、2、3）
00:31:28     root 执行 kill 861863 861917   → 网关 SIGTERM，进程退出（exit 1）
00:31:34     systemd 自动拉起 → pid 909109；同一秒 root 还 nohup 手动起了一个
00:32:05     root 执行 kill 909109          → 又被杀一次（exit 1）
00:32:12     root 执行 su - ubuntu -c 'hermes gateway restart'
00:32:20     systemd 拉起新网关 pid 909629  ← 一直活到现在
```
佐证：
- `/root/.bash_history` 最后几条就是 `kill 861863 861917` / `kill 909109` / `su - ubuntu -c 'hermes gateway restart'`
- `/var/log/auth.log`：00:31:34、00:32:12 两次 `su (to ubuntu) root on pts/1`，与上面命令一一对应
- 网关侧日志：`Shutdown context: signal=SIGTERM under_systemd=yes`、`Gateway stopped by an unexpected signal`（说明没有 planned-stop 标记，即不是 `hermes gateway stop/restart` 的正规路径）

## 排查套路（下次"服务自己挂"照这个走）
```bash
# 1. 是崩了还是被杀了？看 SIGTERM 与 planned-stop 标记
journalctl --user -u hermes-gateway --since "<时间>" --no-pager | grep -E "Shutdown context|Exiting with code|restart counter"
# 2. 有没有 OOM
free -m; journalctl -k --since "<时间>" | grep -iE "oom|killed process"
# 3. 谁在动手？root 控制台痕迹
who -u; sudo tail -20 /root/.bash_history; sudo grep "<日期>" /var/log/auth.log | grep -iE "su|sshd|Accepted"
# 4. 崩溃类证据（Python 层异常）
tail -40 ~/.hermes/logs/gateway-exit-diag.log   # 看 asyncio.run.returned success / SystemExit code
```

## 要点
- Hermes 网关退出码含义：**75 = 收到重启请求**（systemd `RestartForceExitStatus=75` 会拉起）；**1 = 收到信号但没重启请求**（让 systemd 复活）；78 = 不要重启
- 本次两只网关抢锁的问题没发生：手动 nohup 起的那个没存活，systemd 的 909629 稳态运行
- 当前状态：`gateway [default] pid 909629 — systemd @ 433d4068`，qqbot + webhook 均已连接
