# 模型"拒答"伪装成报错 + 标题模型失效排查

## 一、现象：聊天里突然冒"抱歉，您的问题我无法识别"

大哥在 QQ 问「ETH还能稳住吗」，机器人回「抱歉，您的问题我无法识别。」；追问「啥意思」，回「抱歉，没有找到相关的结果。」

**不是崩溃，是模型拒答被 Hermes 当失败处理。**

## 二、定位方法（两条命令搞定）

```bash
# 1. 主对话侧：找拒答记录
grep -n "content_filter\|Model declined" ~/.hermes/logs/agent.log | tail -20
# → Model declined to respond (finish_reason=content_filter). model=deepseek-v4.1-flash
#   refusal=抱歉，您的问题我无法识别。

# 2. 上游侧：看 new-api 实际记账（in/out token + 花费）
cd /home/ubuntu/app/new-api && python3 -c "
import sqlite3,datetime
c=sqlite3.connect('one-api.db')
for r in c.execute('select created_at,model_name,channel_id,prompt_tokens,completion_tokens,quota from logs order by id desc limit 25'):
    print(datetime.datetime.fromtimestamp(r[0]).strftime('%m-%d %H:%M:%S'), r[1],'ch',r[2],'in',r[3],'out',r[4],'\$%.3f'%(r[5]/500000))
"
# → 12:17:47 in=116395 out=11  ← out 只有 11 个 token，就是那句拒答
```

**判据：in 十几万、out 只有个位数 = 上游返了兜底话术，不是真回答。**

## 三、根因

- 那个会话从 9/21 14:32 一路聊到 11.6 万 token 上下文
- 上游走渠道31（opencode.ai zen go）免费贡献者套餐
- 上下文过大 + 免费额度/风控到顶 → 上游开始返「无法识别」这类兜底话术
- **处理：开新会话**，不是模型坏了（短上下文实测正常）

## 五、标题生成模型的两个硬门槛（重点）

标题任务在 `agent/title_generator.py:264-270` 写死了两个约束，**两个都过不了就不能用**：

1. **`max_tokens=64` 硬编码** → 思考型模型 64 个 token 全被 reasoning 吃掉，`content` 为空，静默失败
2. **强制 `response_format: json_schema`（strict）** → 不支持结构化输出的模型直接 400：`does not support JSON schema output mode`

实测（同一条 prompt，max_tokens=64，带 response_format，各 3 次）：

| 模型 | 结果 | 卡在哪 |
|---|---|---|
| **agnes-3.0-flash** | ✅ 3/3，`{"title":"按字段拆分 Excel 文件"}` | 选用 |
| mimo-v2.5 | ❌ 0/3 | 思考型吃满 64 token |
| deepseek-v4-flash（商汤） | ⚠️ 时好时坏 | out 58 啰嗦、429 限流、离线验证常吐空 |
| DeepSeek-V4-Flash（AMD） | ❌ | 不支持 JSON schema |
| Qwen3.8-Flash-Next（AMD） | ❌ | 不支持 JSON schema |
| glm-4.5-air / glm-5.2 | ❌ | 思考型吃满 |
| sensenova-6.8-flash-lite | ❌ | 思考型 + 400 |
| kimi-k3 | ❌ | temperature 只接受 1（标题任务传 0.3） |

**成本对比**（标题任务单次记账）：agnes-3.0-flash `$0.008`，商汤 deepseek-v4-flash `$0.03` —— 差近 4 倍。

> 两个教训：① 别拿"能跑通"的模型直接当标题模型，web_extract 能用的 sensenova 到这就废；② 换模型后**必须用 `generate_title()` 离线跑一遍**，光 curl 测不出 json_schema 和 64-token 这两个坑。

## 六、改 Hermes 配置的正路

`patch` / `write_file` 工具**会拒绝**写 `~/.hermes/config.yaml`（安全策略），必须走 CLI：

```bash
~/.local/bin/hermes config set auxiliary.title_generation.model deepseek-v4-flash
~/.local/bin/hermes config get auxiliary.title_generation.model   # 验证
```

**热加载**：`agent/auxiliary_client.py` 里 `_get_auxiliary_task_config()` 每次调用都 `load_config_readonly()` 读盘 → **改完立即生效，不用重启网关**。

离线验证标题生成：

```bash
cd ~/.hermes/hermes-agent && ./venv/bin/python -c "
from agent.title_generator import generate_title
print(repr(generate_title('ETH还能稳住吗，现在这个行情怎么看')))
"
# → '分析 ETH 行情走势'
```
