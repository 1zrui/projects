# QQ 群不回复 / 群推送失败：群 ACL 与 openid（2026-09-12）

## 现象
- 群 **631502972** 里 @ 机器人没反应
- 定时任务往群推送报 `400 /v2/users/<openid>/messages 请求的资源不存在(用户/群已注销)`

## 根因（两条，都跟"群 openid"有关）
1. **群 ACL 白名单只有一个群的 openid**
   `platforms.qqbot.extra: group_policy=allowlist, group_allow_from=7861772C9D3065DF0986CAE70EF94435`
   代码 `_handle_group_message`：`if not self._is_group_allowed(group_openid, member): return` —— **ACL 不过直接 return，连日志都不打**，所以日志里毫无痕迹，很难查。
   `_entry_matches` 支持 `"*"` 通配；`group_allow_from` 用 `_coerce_list` 解析，**可以逗号分隔多个**。
2. **出站认不出"这是群"**
   `self._chat_type_map`（chat_id → c2c/group/guild/dm）**只在收到该 chat 的入站消息时才写入，纯内存**，网关一重启就空；
   `_guess_chat_type()` 未知时 **默认 "c2c"** → 往群 openid 推送就走了私聊 endpoint `/v2/users/...` → 报"用户/群已注销"。

## 处理（2026-09-12 18:13 实测通过）
1. `hermes config set platforms.qqbot.extra.group_policy open`（备份 `config.yaml.bak-groupopen-*`）
2. **必须重启网关**：群 ACL 在适配器 `__init__` 里读，热改不生效 → 让大哥在 QQ 发 `/restart`
3. 重启后群里 @ 一次 → 日志立刻出现：
   ```
   18:13:46 inbound message: platform=qqbot chat=78BAFCB823704D924249E74E9F5D7850 msg='在'
   18:13:50 Sending response (10 chars) to 78BAFCB823704D924249E74E9F5D7850
   ```
   → **群 631502972 的 group_openid = `78BAFCB823704D924249E74E9F5D7850`**，群通道打通

## 关键知识
- **群 openid 不是群号**，且**随 appid 变**（2026-09-11 换 appid 后旧 openid 全部失效）
- 群 openid ≠ 用户 openid：他本人用户 openid `09E38639299B404FA896B97B7E06D82F`，群 `78BAFCB823704D924249E74E9F5D7850`
- 已知群 openid：
  | 群 | group_openid |
  |---|---|
  | 631502972 | `78BAFCB823704D924249E74E9F5D7850` |
  | 624127517（定时任务推送目标）| `7861772C9D3065DF0986CAE70EF94435`（待核实）|
- 定时任务 deliver 配置在 `~/.hermes/cron/jobs.json` 的 `deliver: qqbot:<group_openid>`
- **群推送的前置条件**：网关启动后该群必须先来过一条入站消息，`_chat_type_map` 才知道它是群；否则推送按私聊发、必失败。要根治得改代码（持久化/配置声明 chat_type），当前未做
