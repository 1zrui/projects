# "一条都不推"的三重死结（2026-09-18）

大哥报「怎么一个 meme 也不推送」。逐层排查，找到**三个各自都能单独把推送量打成 0** 的死结。

## 死结 ①：假量判定误杀（bsc_signal.py）

`24h成交/流动性 > 60倍` → 拦。**BSC 池子流动性普遍几万刀，活跃币天然 90~410x**
（实测连币安官方稳定币 `U` 都被当假量拦了）。

- 改：`60 → 250`（只拦真正离谱的）
- 效果：假量拦截 **116 条 → 2 条**

## 死结 ②：P 级 6 个条件必须全中（bsc_chain.py）

`classify_chain` 的 P 级（起飞前）要求：够新 + 流动性 + 1分钟笔数 + 独立买家 +
净买额 + 最大单笔，**六项全中**。实测 15 分钟扫 50 个新池，**全部卡在"最大单笔<$1200"**
（BSC 早期盘单笔普遍 $100-500）。

- 改：`single_usd 1200→500`、`net 400→200`、`uniq 3→2`、`buys 4→3`
- 再改：**改成评分制**——满足 6 项中的 4 项即推（硬前提"够新 + 有池子厚度"仍必须满足）
- 效果：从 0 触发 → 每 3 分钟触发 1~3 个

## 死结 ③：LP 闸 + 强度闸的自相矛盾（真正的元凶）

两个叠加的闸，各自都让推送归零：

**a) `skip_unlocked_lp: True`**
**BSC meme 的 LP 锁定率实测全 0%**（此前抽查 10 个主流池、含流动性 $132 万的，锁定率全 0%）
→ 开着这闸 = 信号算得再准也永远推不出去。
- 改：`False` + `liq_min_unlocked 150000 → 30000`，走**风险定价**：
  不拦，但标题降级成 `⚠️ 流动性未锁 · 高风险博彩（随时可能被抽池）`（describe_chain 已实现）

**b) `strength()` 里"LP 已锁"占 1/3 分**
LP 未锁是 BSC 常态 → 这一项永远 0 分 → **等于偷偷把门槛抬成"另外两项必须全中"**，自相矛盾。
- 改：第三项换成「池子质量」= LP 已锁 **或** 流动性 ≥$30K
- 再改：**P 级跳过 strength**（P 级已是"6 项过 4 项"，再叠一道就是双重审查）
  A/E 级保留 strength

## 本次改动的纪律教训

1. **patch 的 old_string 覆盖多行 Config 块时，容易连带删掉相邻常量** ——
   实测删掉了仍在使用的 `E_junk_liq`/`A_junk_liq`/`name_dedup_sec`，靠补回救住。
   **改完必须做一次「CFG 引用 vs 定义」完整性检查**（正则提取 `CFG["xxx"]` 与定义块比对）。
2. **日志可能写在文件而不是 journald**：`log()` 同时写 stdout 和 `chain_watch.log`，
   排查"卡在哪一关"必须 grep 文件（`grep 强度不足 chain_watch.log`），只看 journalctl 会漏。
3. **改动必须一次一处 + 每步 py_compile + 重启后看两轮日志**。
4. **别叠加同性质的门槛**：P 级评分制 + strength 闸 + LP 闸 = 三重审查，
   每一道单独看都合理，合起来把推送量打成 0。**同性质的门槛只留一道。**
