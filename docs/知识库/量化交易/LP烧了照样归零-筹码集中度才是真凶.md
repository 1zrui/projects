# 事件

大哥收到推送：
```
⚡ 早期梗币 · 09-19 15:46:22
牛马人生（BSC）  0xbb1351fd78e47b85fb55b56a2dea3872e964ffff
5min +203% · 成交 $15.9K · 买60/卖4
流动性 $44.1K · 池龄 5 分钟
🔥 名字命中热词：人生
风控：蜜罐 否 ✅
LP：未锁（在部署者钱包里，随时能抽）❌
持币 19 个地址 · 前十占比 65% · 最大单一地址 63%
```
→ 一天后归零。**推送里明明写着「LP：未锁 ❌」还是推出去了。**

# 根因（两层）

## ① 表面：LP 闸被绕过

E 级（早期梗币）推送路径的 LP 闸判据是**链上直读**（`lp_locked_pct`，优先级高于 GoPlus），
而链上直读算出的是 **95% 已锁** → 放行。GoPlus 说"未锁"被忽略了（代码里注释就写着"GoPlus 对新池不靠谱，能用链上直读就用链上直读"）。

**同一份推送里两个数据源打架：显示用 GoPlus（未锁），闸门用链上直读（95% 锁）。**

## ② 真凶：LP 烧了 ≠ 安全

链上实测（归零后）：
```
LP 总量              1272.75
黑洞 0xdead 持有     1209.12  =  95.00%   →  lp_locked_pct = 95%  →  闸门放行 ✅
池内储备             token1(WBNB) = 0.000478 BNB   ← 已被抽干
```

**他的套路：95% 的 LP 确实烧了（看起来很安全），但手里握着 80.66% 的币，直接往池子里砸，把 BNB 换走。**

持币结构（链上直算，已排除池子/黑洞）：
```
0x686b054995986897db1f100ff971fcc7746eb857   80.66%   ← 部署者
0x57c6b27e...（池子）                          17.26%
0x0000...dead（黑洞）                           0.16%
其余 741 个地址                               ~1.9%
```
→ **流动性 $44.1K → $0.72，价格 -100%。**

**推送里其实已经写着「最大单一地址 63%」——那才是真凶，但它只被当成一行提示，没有拦推送。**

# 修复

给 A 级和 E 级**都**加「筹码集中度闸」（`bsc_signal.py`）：

```python
_chip = holders_stats(p["addr"], pair=p.get("pair"))
if _chip:
    _t1  = _chip.get("top1_pct")  or 0   # 最大单一地址（已排除池子/黑洞）
    _t10 = _chip.get("top10_pct") or 0
    if _t1 >= CFG["max_top1_pct"] or _t10 >= CFG["max_top10_pct"]:
        log_line(f"[跳过-筹码集中] ...")
        continue
```

CFG 新增：
```python
"max_top1_pct": 20,    # 最大单一地址 ≥20% → 能砸盘归零
"max_top10_pct": 50,   # 前十合计 ≥50%
```

回测（拿牛马人生真实数据）：
```
① LP 闸:   95.0% 已锁        →  通过 ✅（所以旧逻辑推了）
② 筹码闸:  最大单一地址 80.7%（阈值 20%）  →  ✅ 拦住
            前十合计     82.6%（阈值 50%）
```

# 教训

1. **LP 烧了 ≠ 安全**。还要看筹码分布。部署者握着大量币，一样能砸盘归零，跟 LP 锁没锁无关。
2. **同一份推送里两个数据源打架是危险信号**。显示用 GoPlus、闸门用链上直读 → 用户看到的和程序判的不一致。
3. **风控闸必须覆盖所有推送路径**。之前只给 `bsc_chain.py` 的 P 级加了 LP 硬闸，`bsc_signal.py` 的 E 级/A 级是另一条路由，容易被漏掉。
4. **改完代码必须重启服务才生效**。`systemctl restart` 要交互认证，走大哥在 QQ 发 `/restart`（exit 75，systemd 自动拉起）。**改完不重启 = 白改**，这次改了之后旧进程又推了一次同一个币。
