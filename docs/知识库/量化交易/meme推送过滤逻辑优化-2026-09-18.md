# meme 推送过滤优化（2026-09-18）

## 背景
大哥：「不要什么币都给我推，要有过滤逻辑，优化逻辑」

恢复推送后实测：bsc-chain 25 条 / bsc-signal 33 条 / flap-watch 13 条（7 天）≈ 10~13 条/天。

## 三个改动

### ① 补上漏的闸门（flap_watch.py）
**漏洞**：flap-watch 调 `push_qq` 时**没传 `gate_ca`** → 完全绕过冷却与全局限流，三个服务各自为政。
```python
# 改前
bs.push_qq(f"🆕 Flap 新币…")
# 改后
bs.push_qq(f"🆕 Flap 新币…", gate_ca=tok, kind="FLAP")
```

### ② 信号强度硬门槛（bsc_chain.py）
新增 `strength(p, w1, w5)`，三项计分：
- 钱在进（1 分钟 ≥4 笔买 且 净买入 > 0）
- 有人喊（`bsig.find_shill` 3 小时窗口命中）
- LP 已锁（≥50%）

**`sig < 2` → 不推，只记日志** `[跳过-强度不足]`。以前 🟠（只成立一项）也在推，是"什么币都推"的主要来源。

### ③ 结果追踪（push_tracker.py，最关键）
**过去所有门槛都是事前规则，从未验证有效性。**

- `push_qq` 推送成功后追加一行到 `push_tracker.jsonl`（ts / ca / kind / 标题）
  - 常量 `TRACK_F` 定义在 bsc_signal.py（注意：定义在文件后部，但函数运行时才解析，无问题）
- `push_tracker.py --fill`：对满 25 小时的记录，找主池 → 拉 GeckoTerminal 小时 K 线 → 回填 1h/6h/24h 涨跌 + 期间最高
- `push_tracker.py --report`：按级别（A/E/P/FLAP/SOCIAL）分组统计中位涨幅、涨>50% 比例、跌>50% 比例
- cron：`17 * * * *` 每小时回填、`0 9 * * *` 每天 9 点出报告

**目的**：用数据反推「哪条规则真筛出了会涨的币」，而不是继续拍脑袋调阈值。
