# 云服务器磁盘/内存清理记录（2026-09-11）

## 结论
- **内存不用管**：3.6G 总量，可用 2.3G，网关进程仅占 240M，无泄漏。swap 用 352M / 1.9G 属正常。
- **磁盘清了约 3G**：`21G 已用 / 55%` → `18G 已用 / 48%`（40G 盘，可用 20G）。

## 清理项（都在 ~/.hermes 相关机器上，安全）
| 项目 | 释放 | 命令 |
|---|---|---|
| journald 系统日志（422M→100M） | 302M | `sudo journalctl --vacuum-size=100M` |
| apt 下载缓存 | 281M | `sudo apt-get clean` |
| uv 包缓存 | 336M | `rm -rf ~/.cache/uv`（会自动重建） |
| `.git` 垃圾包回收（813M→73M） | ~740M | `cd ~/.hermes/hermes-agent && rm -f .git/objects/pack/tmp_pack_* && git gc --prune=now` |
| `/tmp` 里 node 安装包残留（v20+v22 共 362M）+ node-compile-cache + export_test + tmp.* | ~410M | `sudo rm -rf /tmp/node-v20*/ /tmp/node-v22*/ /tmp/node-compile-cache /tmp/export_test` |
| `~/.local/node22.bak`（旧版备份） | 193M | `rm -rf ~/.local/node22.bak` |
| pnpm store（孤儿缓存，机器上根本没装 pnpm） | 762M | `rm -rf ~/.local/share/pnpm/store ~/.cache/pnpm` |

## 关键教训
1. **`.git` 会悄悄膨胀**：`hermes-agent` 仓库只有 31 个 commit，pack 却有 737M —— 全是反复 clone/fetch 留下的不可达对象 + 一个中断残留的 `tmp_pack_*`。`git gc --prune=now` 一次回收 740M。终端里有提示 `warning: garbage found: .git/objects/pack/tmp_pack_*` 就是这个信号。
2. **pnpm store 可能是孤儿**：`~/.local/share/pnpm/store` 有 635M，但 `which pnpm` 找不到、`node_modules` 里没有 `.pnpm`、全盘搜不到指向 store 的软链 → 纯垃圾。判断方法：先确认 `node_modules/.pnpm` 不存在、再 `find -type l -lname "*pnpm/store*"` 为空，才能删。
3. **删缓存前必须查依赖**：
   - `~/.local/node22` 在 `~/.bashrc:121` 的 PATH 里 → 保留；`node22.bak` 才可删。
   - `~/.cache/ms-playwright`(656M)、`~/.cache/chrome-debug`(312M) 看着像缓存，但**豆包登录态在 chrome-debug 里**，删了要重新登录 → 一律不动。
   - docker + containerd 共 3.6G，青龙面板在跑，`docker system df` 显示 0 可回收 → 不动。
4. `uv` 缓存删了会有正在运行的子进程仍持有已删除文件（Linux 特性，不影响运行），下次启动 uv 会自动重新下载。

## 定期清理建议
- 每月跑一次：`journalctl --vacuum-size=100M`、`apt-get clean`、`rm -rf ~/.cache/uv`、`git gc`。
- `/tmp` 的 node 安装包残留每次升级 node 后都会留一份，可顺手删。
