# 京东「带图评价晒单」脚本停用排查（2026-10-10）

> 结论：**脚本被作者远程停用了，不是 CK 过期、不是青龙的问题。** 别在这上面耗。

## 现象
青龙任务 `86 | 带图评价晒单 | task shufflewzc_faker2/jd_AutoEval.js`（状态：禁用，手动触发也能跑）

日志只输出 4 个字，0.4 秒就结束：
```
屏蔽差评内容关键词：["垃圾","质量差","差评","好差","欺骗"]

未知错误！

🔔带图评价晒单, 结束! 🕛 0.437 秒
```
对比 2026-08-30 的正常日志：那次跑 24 秒、评价了 2 个商品、晒图成功。

## 排查路径（可复用）
1. **先补依赖，别急着下结论**：脚本 `require("sharp")`，容器里**没装** →
   `docker exec qinglong bash -lc "cd /ql/data/scripts/shufflewzc_faker2 && npm install sharp --no-package-lock --legacy-peer-deps"`（7 秒装好，vips 8.18.7）。
   补上后**仍然报同样的错** → 说明不是它。
2. **拿调用栈**：脚本是混淆的、异常被自己 catch 吞掉。用 `NODE_OPTIONS="--require <patch.js>"` 预加载一个 patch，拦截 `console.log`，当输出含「未知错误」时打印 `new Error().stack`：
   ```
   at console.log (/ql/data/scripts/shufflewzc_faker2/zz_debug_patch.js:8:19)
   at /ql/data/scripts/shufflewzc_faker2/jd_AutoEval.js:6:153339
   ```
   → 定位到 `if(WCkoQRp == '未知错误！'){ console.log('未知错误！'); return }`。
3. **改一份调试副本**（别动生产脚本）：`sudo python3` 把关键分支注入打印，生成 `jd_AutoEval_dbg.js`，跑出来：
   ```
   [DBG-REQ] opts= {"url":"https://6dy.oss-cn-hangzhou.aliyuncs.com/pinjia.json","timeout":30000}
   [DBG-CB] arg1= null  arg2= 200  arg3= ''
   [DBG-WC] now= 20251224  expect= 20251224
   未知错误！
   ```
   → 脚本开机就拉作者的远程开关文件 `pinjia.json`，**HTTP 200 但 body 空**，拿不到配置就判自己不可用。
4. **直连验证（定案）**：
   ```bash
   curl -s --noproxy '*' -m 20 -o /tmp/p.json -w 'code=%{http_code} size=%{size_download}\n' \
     https://6dy.oss-cn-hangzhou.aliyuncs.com/pinjia.json
   # code=200 size=0   ← 空文件，作者清空了
   ```

## 处置

- `sharp` 依赖保留（脚本将来恢复要用）。

## 经验
- 京东类脚本常带「远程开关」：开机拉作者 OSS/CDN 上一个 json，拿不到就自锁。**遇到秒退+一句含糊报错（"未知错误！"），先怀疑远程开关，别怀疑 CK**。
- 判断是"我们的问题"还是"作者停了"：直接 curl 那个远程文件，**200 + size 0 就是作者关闸**，本地怎么修都白搭。
- 混淆脚本排错三件套：`grep -o "require(...)"` 看依赖 → `NODE_OPTIONS --require` 打 patch 抓 stack → 生成 `_dbg.js` 副本注入打印（绝不改生产文件）。
- 青龙目录属主是 root，写文件要 `sudo cp /tmp/x.js <目标>`。
